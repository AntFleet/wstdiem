## 3. THE BLOCKER — issue #13 (P0): OPEN omits the user's equity

`LoopExecutorV2._executeOpenInCallback` (`contracts/v2/LoopExecutorV2.sol:274-279`) supplies **only** the
flash-borrowed principal as collateral — the user's equity is never transferred in and never combined.
Two defects: (1) no `_safeTransferFrom(collateralToken, owner, executor, equity)` in the open path;
(2) line 278 overwrites (`=`) instead of accumulating (`+=`), and there is **no signed equity field** in
`OpenBounds` at all (`supplyCollateralAssets` is seeded from `minWstDiemReceived`, a slippage floor).
Post-open HF ≈ LLTV/NAV ≈ 0.86 < 1.05 regardless of leverage. Spec `PROTOCOL.md:269` requires
"combining … the user's transferred wstDIEM". Present since the first commit `b40e607`; unrelated to the
EIP-170 refactor. **Opening a leveraged loop is non-functional as deployed.**

The SDK already carries the equity value (`BuildOpenParamsInput.collateralAmount`) — it just isn't signed
into a bound the contract reads.
